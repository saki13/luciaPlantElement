# 关卡设计准则（基于 PvZ 拆解 + 我们的系统）

> 参考：
> - [从《植物大战僵尸》看如何设计关卡的节奏](https://game.3loumao.org/115453)
> - [关于塔防游戏的一点拙见](https://www.gameres.com/forum/t/454620)
> - [如何高效设计游戏——塔防游戏设计方案](https://www.gameres.com/183975.html)

## 一、PvZ 是怎么做的（四条核心机制）

### 1. 战力曲线：每波有"战力上限"，而不是固定出怪

每关先给每波定一个**战力上限**，再从本关僵尸卡池里**按权重抽卡直到填满**。

- 普通僵尸战力 1、路障 2、铁桶 4、巨人 8…
- 上限曲线近似 `y = kx + b`：早期平缓，后期陡升。
- **调 k 和 b 就等于调整关难度**——这是关卡难度的主旋钮。

### 2. 权重随波次漂移

普通僵尸的抽取权重**随着波次递减**，后面的波次越来越偏向硬怪。
同一关内因此有"逐渐变强"的体感，而不是简单加量。

### 3. 自适应波次间隔（最妙的一条）

下一波不是在固定时间刷，而是：

> 本波僵尸血量低于阈值 **或** 等待超过 X 秒 → 刷下一波

- 打得快 → 节奏加快，高手不无聊
- 打得慢 → 游戏给你时间铺场，新手不被压死
- 玩家甚至没察觉，但这就是"休闲与硬核都舒服"的关键

### 4. 情报节奏：旗帜波预告

每 10 波一个旗帜波，**提前播报"一大波僵尸即将来袭"**。
这让玩家能做规划（什么时候丢樱桃），而不是纯临场反应。

> 原文一句很到位：**"策略是在计划和应变之间取平衡。如果流程无法预测，玩家就疲于临场反应，无法做长远规划。"**

## 二、关卡外的节奏控制

| 做法 | 我们的对应 |
|---|---|
| 简单机制在前、复杂机制在后 | M1 经典植物 → M2 能力机制 → M3 自造克制 |
| 新僵尸预留 **2~4 关**教学，并给出对应植物解 | M1 每关发一株、M3 每关发一株正好是"给解" |
| 每 5 关插入小游戏/变奏，避免疲劳 | **我们还没做**，可以用"挑战关"当变奏 |
| 关键新增：不要隐藏 AI 调整，会破坏信任 | 我们的 rescues / 首车救援必须**明说** |

## 三、我们的系统映射

| PvZ 概念 | 我们的实现 | 状态 |
|---|---|---|
| 僵尸战力 | `enemy.budget`（普通 1 / 路障 2 / 铁桶 4 / 巨人 8） | ✅ 已有 |
| 每波战力上限 | `cap_base` / `cap_max` + `waves` | ✅ 已有 |
| 卡池 | 关卡 `spawn.allowed` | ✅ 已有 |
| 抽卡填满 | `wavegen` 按 budget 抽 | ✅ 已有 |
| 权重漂移 | **未实现**（目前均匀抽） | ❌ 待做 |
| 自适应波次间隔 | **未实现**（固定间隔） | ❌ 待做 |
| 旗帜波预告 | **未实现** | ❌ 待做 |

**结论：我们的骨架是对的，缺的是三样"节奏调味"**：
权重漂移、自适应刷怪、大波预告。

## 四、给我们的设计规则

### 4.1 每关的难度由三个数决定

```
waves     波数        —— 关卡的"长度"
cap_base  起始战力    —— 开场压力
cap_max   末期战力    —— 高潮强度
```

线性插值：第 i 波的战力上限 ≈ `cap_base + (cap_max - cap_base) * i / waves`

**不要**用"多刷几只普通僵尸"来提升难度——那是加压不是加趣味。
提升难度应该靠 **cap_max** 和 **卡池质量**（加入更难的类型）。

### 4.2 新敌人必须"两关法则"

新僵尸登场后，**至少 2 关内它的出现概率要高、且同关要给出对应的解**：

| 新敌人 | 对应解 | 给出方式 |
|---|---|---|
| 格挡盾兵 | 破盾 | M2 挑战关引导造破盾植物 |
| 护甲（铁桶/鳞甲） | 穿甲 | 同上 |
| 高速 | 减速 | 同上 |
| 抛射僵尸 | **治疗植物**（守后排） | **M3 需要补这条引导** |
| 亵渎光环 | 速杀 / 治疗 | 后期内容 |

### 4.3 允许"Bot 打不过"，但必须是"设计能解"

**校准门禁里 Bot 胜率 0 ≠ 关卡不可通关。**

Bot 的卡池只有预置植物，它**不会按关卡特点去设计克制植物**。
所以：

- M1/M2：Bot 应当能过（这些关卡的解法在预置卡池内）
- M3：**允许 Bot 过不了**，衡量的标准应该是——
  **"存在一株玩家可造的植物，能让这关通关"**

因此 M3 的验收应从"Bot 胜率"改成"**存在解**"：
用一批候选配装（破盾/穿甲/减速/治疗/高DPS）分别跑，只要有任一套能过，就算达标。

### 4.4 抛射僵尸的解 = 治疗植物（用户指定）

抛射僵尸越过前排打后排，堆肉盾无效。解法链条：

1. **治疗植物**：范围治疗撑住后排
2. **速杀**：高 DPS 先杀掉它
3. **分散站位**：后排不留一列

所以 M3 加入抛射僵尸的关卡，**必须先给玩家治疗植物**（或工坊可造），
否则玩家会陷入"知道怎么打但没牌"的挫败。

**待办**：`heal` 轴目前在 `design_slots` 里定义了（3/4/5 档 = 1×1 / 2×2 / 3×3，
治疗量=攻击力×2，频率=攻速），但**引擎还没实现治疗结算**。

---

## 五、立即可做的三件事（按性价比排序）

1. **实现治疗结算**（引擎小改，解锁抛射僵尸的正解）
2. **M3 验收改成"存在解"**（校准脚本改造，不再用 Bot 胜率一刀切）
3. **加权抽卡 + 自适应刷怪**（节奏调味，直接提升手感）

大波预告（旗帜波）可以放在 UI 层，成本最低、体感最强。
