# 挑战关流程与两种稀有机制

> 设计方口述，本轮落档。挑战关从 6 关缩为 **4 关**。

---

## 一、挑战关只保留 4 关

| # | 关卡 | 僵尸特性 | 玩家要造的克制能力 |
|---|---|---|---|
| 1 | `m2_shield` | **格挡** | 破盾 |
| 2 | `m2_armor` | **护甲** | 穿甲 |
| 3 | `m2_speed` | **高速** | 减速 |
| 4 | `m2_swarm` | **人海 / 召唤** | 溅射 / 范围 |

**删掉的两关及理由**：

- `m2_weight`（重量 / 巨人）：**T6 植物根本推不动巨人**。
  这一组其实是"**僵尸 counter 植物**"的关系，不是"植物 counter 僵尸"，
  不适合当引导关。击退/力道是后期内容（破格、慢攻速才推得动）。
- `m2_control`（控制）：我们**没有"能控制植物"的僵尸**，这一对不存在。

## 二、挑战关的完整流程（每个挑战关都一样）

以 `m2_shield`（格挡）为例：

```
1. 玩家带着前 18 关获得的经典植物进入挑战关
      ↓
2. 打不过带格挡的僵尸（必然，前 18 关没有任何破盾手段）
      ↓
3. 损失第一辆小车 → 触发「救援」：
      · 清除场上全部僵尸
      · 每一行补种一株「冰西瓜」
      · 帮玩家把这一关稳住 / 通关
      ↓
4. 自动引导玩家进入工坊，设计一株带「破盾」的 T6 植物
      ↓
5. 带上新造的植物重打这一关 → 通过
```

**之后每个挑战关都重复这个循环**：先被某种特性卡住 → 救援兜底 →
引导造出对应的克制植物 → 通关。

### 2.1 这个设计解决了什么

- **永不死档**：第一辆小车就是"教学保险"，玩家不会因为机制不懂而卡死。
- **教学即动机**：卡住的那一刻，玩家**自己**产生了"我需要破盾"的念头，
  比弹窗讲一百遍都有效。
- **造出来的植物立刻有用**：不是"造完放在库里"，而是下一关的钥匙。

### 2.2 待实现的引擎能力

| 项 | 说明 |
|---|---|
| 首车损失事件 | 检测"第一次被僵尸进屋"，而不是直接判负 |
| 救援清场 | 全屏清除僵尸（不含 Boss） |
| 每行补种冰西瓜 | 在每行最右可种格放一株 `winter_melon` |
| 引导流程 | 关卡失败/救援后弹出"去工坊造带 X 能力的植物" |

> 注意：**当前引擎是"掉一辆车 = 立刻失败"**，需要改成"前 N 辆车是缓冲"。

## 三、地雷机制（土豆雷类）

三种稀有机制的组合，不是"种下即爆"：

| 阶段 | 行为 |
|---|---|
| 1. **延迟成长（arm）** | 种下后需要 `arm` 秒"埋好"，此期间**不触发、不爆炸** |
| 2. **接近触发（trigger）** | 埋好后，敌人进入 `trigger_radius` 内才触发 |
| 3. **一次性爆炸（explode）** | 触发后按爆炸半径与伤害结算，随即消失 |

### 3.1 与樱桃炸弹的区别

| | 樱桃炸弹 | 土豆雷 |
|---|---|---|
| 触发 | **种下即炸**（fuse 固定延迟） | **等敌人踩**（接近触发） |
| 时机 | 玩家主动 | 玩家预判 + 被动等待 |
| 定位 | 救场 | 埋伏 / 陷阱 |

### 3.2 数据格式（建议）

```json
"combat": {
  "on_place": {
    "arm": 4.0,
    "trigger_radius": 0.6,
    "explosion": { "radius": 0.5, "damage": 1800 }
  }
}
```

- 现有引擎已支持 `on_place.fuse`，**加 `arm` 与 `trigger_radius` 两个字段即可**：
  - 有 `fuse` → 定时爆炸（樱桃）
  - 有 `arm` + `trigger_radius` → 埋雷 + 接近触发（土豆雷）

### 3.3 土豆雷的原版数值

| 项 | 值 |
|---|---|
| 阳光 | 25 |
| CD | 30s |
| 埋雷时间 | 4s（原版约 15s，可缩短） |
| 触发半径 | ~0.6 格 |
| 爆炸伤害 | 1800（单体/小范围） |
| 爆炸半径 | 0.5 格（基本单体） |
